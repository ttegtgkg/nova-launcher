fix: 下载前先摸底，进度条分母不再边跑边涨

用户指出：装整合包时进度条能从 100% 跳回 62%。

根因是 bytesTotal 只增不减：
  byByte = bytesDone / bytesTotal
下完 63 MB 的整合包时 63/63 = 100%，一进「安装游戏版本」，
bytesTotal 又被加上游戏本体的大小，立刻变成 63/88 = 71%。
分母边跑边涨，进度自然往回跳。

改：

- curseforge.mjs 新增 cfFileMeta()：单查一个文件的 size + downloadUrl
- /api/cf/pack/install 在下载前先扫一遍：解析 manifest 后并发查每个模组的
  文件大小，同时把游戏本体（client jar + 依赖库 + 资源文件，从 version json
  和 asset index 算）也估进来，一次性把 bytesTotal 定下来
- 预扫时顺手把 downloadUrl 取回来，真正下载时少打一次 API
- 模组下载挂上 onProgress，之前只有 tprogress 计文件数、不报字节
- 失败清单也记下来（missedList），不再只报「8 个内容失败」这种数字

实测两次（From the Fog Reimagined，165 个模组）：

  第一版预扫（只算整合包 + 模组）：
    分母 4.9 MB → 装 MC 时暴涨到 1096 MB，倒退 3 次
  第二版（补上游戏本体）：
    分母 1798 MB，倒退降到 2 次

剩下的 2 次倒退来自「运行安装器」和「补全前置模组」—— 这两步要下多少
事先根本不知道（NeoForge 安装器自己决定，补前置要查完才知道还缺谁）。
只要还用一个全局百分比表示，这两处就必然会往下跳。

正解应该是不再猜总量：改成「第 3/7 步 · 本步 45%」这种分阶段进度，
每段内部单调递增，段落切换只更新步数。这需要改前端呈现方式，
不是再加一行补丁能解决的。
